# 阅读窗口暗色卡片阴影清晰度补充设计

## 1. 问题

阅读窗口卡片当前使用由 `accent` 派生的零偏移双层阴影。明亮主题中的 `accent` 比页面和卡片背景更暗，因此表现为正常投影；暗色主题中的 `accent` 比背景更亮，因此表现为暖色光晕。

暗色页面背景 `#151210` 与卡片背景 `#211C17` 的对比本身较低。亮色光晕再经过 `24px` 模糊，并在两张卡片的 `30px` 间隙内相遇，会让卡片边界显得发虚。

## 2. 目标与约束

- 暗色主题下卡片边界不再呈现暖色光晕。
- 大纲卡片和阅读卡片继续使用完全相同的阴影。
- 阴影继续保持水平、垂直偏移均为 `0`，四周强度一致。
- 明亮主题的现有阴影保持不变。
- 不增加实体边框或 inset 描边。
- 不修改窗口 inset、卡片宽度、卡片间距、正文宽度、正文 padding、圆角或组件结构。

## 3. 方案比较

### 方案 A：暗色主题使用中性黑色阴影（采用）

只在有效主题为暗色时覆盖 `--reader-card-shadow` 的颜色，保留现有模糊半径、负扩展值和零偏移结构。

优点：

- 直接消除暖色光晕根因。
- 仍然是四周均匀的无方向阴影。
- 不引入边框，不改变布局几何。
- 明亮主题完全不受影响。

### 方案 B：降低暗色 Accent 阴影透明度

能够减弱光晕，但阴影仍比背景更亮，边界发虚的方向不会消失。

### 方案 C：增加 1px 边框或 inset 描边

边界最清晰，但会重新引入实体分界线，不符合当前阅读窗口的无硬边框约束。

## 4. 实现

保留默认明亮主题变量：

```css
--reader-card-shadow:
  0 0 24px -8px color-mix(in srgb, var(--accent) 18%, transparent),
  0 0 8px -2px color-mix(in srgb, var(--accent) 10%, transparent);
```

在根节点有效主题为暗色时，仅覆盖颜色：

```css
:root[data-theme-effective-mode="dark"] .reader-preview-shell {
  --reader-card-shadow:
    0 0 24px -8px rgb(0 0 0 / 52%),
    0 0 8px -2px rgb(0 0 0 / 34%);
}
```

第一层负责外侧柔和暗化，第二层负责贴近卡片边缘的暗化。两层都不带方向偏移。

## 5. 验收标准

1. 明亮主题计算后的卡片阴影与当前版本一致。
2. 暗色主题两张卡片使用相同的中性黑色双层阴影，不再包含 Accent 暖色光晕。
3. 暗色主题下卡片边界比当前版本清晰，卡片间隙没有明显亮带。
4. 两张卡片的四周阴影仍然均匀。
5. `18px` 窗口 inset、`336px` 大纲宽度、`30px` 间距、阅读区 `96px` 水平 padding 和正文宽度行为保持不变。

## 6. 验证

- 静态测试先确认旧实现缺少暗色专用阴影覆盖，再以最小 CSS 修改转为通过。
- `pnpm qa:reader-ui` 覆盖明亮桌面、暗色桌面和最小阅读窗口高 DPI 场景，并核对计算阴影及原有几何值。
- 人工检查新鲜暗色截图，确认卡片左侧、中间间隙、顶部和右侧不再出现暖色模糊光带。
- 执行 `pnpm test`、`pnpm lint`、`pnpm format:check`、`pnpm build`。
- 执行 `pnpm tauri build --no-bundle --ci` 生成新的测试 EXE，不生成安装包。
