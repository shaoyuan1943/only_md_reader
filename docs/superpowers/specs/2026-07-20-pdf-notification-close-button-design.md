# PDF 导出通知关闭按钮设计

## 背景

PDF 导出成功通知会在 3 秒后自动关闭；错误通知为便于用户阅读失败原因会持续显示。当前通知状态层已经支持关闭动画和移除通知，但通知 DOM 没有提供可点击的关闭入口，导致错误通知只能通过关闭阅读窗口或错误数量淘汰而消失。

本设计以用户 2026-07-20 提供的 SVG 为唯一关闭图标，并更新 `docs/implementation-worklist.md` 第 16.12 项中“错误通知不提供操作按钮”的旧约束。

## 已确认交互

- 每一条 PDF 导出通知（成功和失败）右上角都显示关闭按钮，保持交互一致。
- 点击关闭按钮后，当前通知进入既有从右向左退出动画，动画结束后从 DOM 移除；其他通知不受影响。
- 错误通知仍不自动消失，直到用户点击关闭按钮，或活跃错误超过三条时由既有上限策略关闭最旧错误。
- 成功通知仍在 3 秒后自动关闭；用户可在 3 秒内提前点击关闭。提前关闭时清理该通知的自动关闭计时器。
- 关闭按钮使用原生 `button type="button"`，可由键盘聚焦和触发，提供 `aria-label="关闭通知"` 与同名 tooltip。

## 视觉规格

- 按钮绝对定位在通知框右上角，不改变通知框的外部宽度、三边 `6px` inset、`14px` 圆角或现有阴影。
- 点击区域为 `24px × 24px`，SVG 视觉尺寸为 `16px × 16px`；按钮使用透明背景，hover / focus-visible 仅显示轻量主题色底纹和现有焦点环。
- SVG 保留用户提供的 `viewBox="0 0 1024 1024"` 和两条 `path d` 数据，移除图标平台生成的 `t`、`p-id`、固定 `width="200"`、`height="200"` 等无运行意义属性；路径使用 `fill="currentColor"`，随成功/失败通知文字颜色变化。
- 通知标题和详情为关闭按钮预留右侧空间，继续保持单行和 `text-overflow: ellipsis`。完整文本仍保留在 DOM，不做字符串截断。

## 代码边界

- `ReaderNotificationStack` 新增 `onClose(id)` 回调，并在每条通知中渲染关闭按钮。
- `ReaderPreviewWindow` 复用现有 `closeReaderNotification` 状态函数；手动关闭成功通知时同步清理 `readerNotificationSuccessTimersRef` 中对应计时器。
- `App.css` 只增加通知按钮和文字避让样式，不改通知栈定位或通知卡片几何基线。
- 正式分支先完成实现和验证；临时强制失败预览分支随后同步同一实现，保留其“导出必然失败且不写 PDF”的临时行为。

## 验证

- 测试先失败：锁定按钮语义、用户 SVG 路径、`onClose` 连接以及文字右侧避让样式。
- `pnpm qa:pdf-export` 实际点击错误通知关闭按钮，确认退出动画后该通知从 DOM 消失；同时确认成功通知也有按钮、可提前关闭，长文本仍为省略号。
- `pnpm qa:reader-ui` 验证阅读窗口布局未回归。
- 运行 `pnpm test`、`pnpm lint`、`pnpm format:check`、`pnpm build`，并按项目规则构建新的无安装包测试 EXE：`pnpm tauri build --no-bundle --ci`。
- 人工核对明亮主题和暗色主题下按钮位置、颜色、点击区域及通知文字不与图标重叠。
