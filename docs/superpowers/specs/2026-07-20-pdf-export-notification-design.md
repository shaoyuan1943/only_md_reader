# PDF 导出通知框调整设计

日期：2026-07-20

## 1. 目标

调整阅读窗口左下角的 PDF 导出通知，使通知宽度与大纲卡片扣除水平内边距后的内容宽度一致，并明确区分通知标题与结果详情。

## 2. 用户可见行为

### 2.1 导出成功

通知固定显示两行：

1. 第一行：`PDF文件已导出！`
2. 第二行：原生导出结果 `outputPath` 中的 PDF 文件名，不显示目录路径

文件名提取同时兼容 Windows 反斜杠路径和正斜杠路径。例如：

- `E:\notes\readme (2).pdf` 显示为 `readme (2).pdf`
- `/Users/name/notes/readme.pdf` 显示为 `readme.pdf`

成功通知继续沿用现有自动关闭时序和退出动画。

### 2.2 导出失败

通知固定显示两行：

1. 第一行：`PDF导出失败！`
2. 第二行：当前失败分支产生的具体原因

第二行不得使用笼统占位文案覆盖真实错误：

- 图片等资源等待超时时，显示现有资源超时原因。
- 原生 PDF 写入失败时，显示原生层返回的错误原因。
- 导出准备阶段异常时，显示准备阶段异常原因。

错误通知继续沿用现有错误堆叠、最多三个活跃错误和手动状态管理逻辑。

## 3. 数据结构与渲染

`ReaderNotification` 从单个 `message` 字段调整为：

- `title`：第一行固定结果标题。
- `detail`：第二行文件名或错误原因。

通知组件使用两个独立文本元素渲染，便于设置语义、间距、字重、截断和自动换行；不使用换行符拼接单个字符串。

成功分支直接使用 `startPdfExport` 已返回的 `outputPath`，不增加原生命令或第二次文件系统查询。文件名提取封装为纯函数并单独测试。

## 4. 布局

当前大纲卡片宽度为 `336px`，水平内边距为 `17px`。通知内容宽度应为：

```text
336px - 17px - 17px = 302px
```

通知栈左边缘应与大纲卡片内部左侧内容边缘对齐：

```text
窗口卡片 inset 18px + 大纲卡片左 padding 17px = 35px
```

通知项占满通知栈宽度，继续保留现有圆角、颜色、阴影、动画、左下角位置和主题适配。第二行允许在通知宽度内换行，不能溢出通知框。

共享的大纲宽度与 padding 应通过 CSS 自定义属性表达，避免通知宽度和大纲卡片尺寸形成互不关联的魔法数字。

## 5. 可访问性

- 错误通知继续使用 `role="alert"`。
- 成功通知继续使用 `role="status"`。
- 两行均作为通知内容被辅助技术读取。
- 仅改变内容结构和尺寸，不增加新的交互控件。

## 6. 验证

实施时先补回归测试并确认失败，再写最小实现使其通过。

自动验证至少覆盖：

- Windows 路径仅显示文件名。
- 正斜杠路径仅显示文件名。
- 成功通知的固定标题和动态文件名。
- 错误通知的固定标题和具体原因。
- 通知栈宽度为 `302px`、左边缘为 `35px`，通知项占满栈宽。
- 通知仍在打印媒体中隐藏。
- `pnpm test`、`pnpm qa:pdf-export`、`pnpm qa:reader-ui`、`pnpm build`。
- 按项目规则生成新的测试 EXE：`pnpm tauri build --no-bundle --ci`。

## 7. 不在本次范围内

- 不改变 PDF 文件命名规则、保存目录或冲突递增规则。
- 不改变导出按钮的位置、尺寸、图标、提示文字或触发方式。
- 不改变成功通知持续时间、错误通知数量上限或通知动画方向。
- 不增加打开 PDF、打开所在目录、复制路径或关闭按钮。
